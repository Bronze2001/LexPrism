# 千问办公部署与联调

2026-09-10。Skill 仍在迭代中；法律数据连接器仅在千问办公中维护。本仓库不保存可导入 MCP 配置、凭据、本地 MCP 转发器或本地服务器。

## 1. 取得权限后的顺序

1. 查看当前账号的技能安装/创建入口与组织权限，导入`lexprism`技能目录或打包ZIP。包内应为`lexprism/SKILL.md`及`lexprism/references/`，包含六份参考；原始律师材料、评测答案和凭据均不放入包内。
2. 如果使用组织Skill上传入口，官方说明要求ZIP顶层目录与技能名称匹配，大小不超过10MB；个人/专家入口以实际界面为准，不假定所有角色入口相同。[技能说明](https://help.aliyun.com/zh/qwenwork/skills)、[组织技能管理](https://www.alibabacloud.com/help/zh/qwenwork/skills-management)
3. 在千问办公现有连接器中确认北大法宝及已启用的海外法源，再开启一个新对话测试技能触发和工具访问。
4. 先使用非敏感、已知出处的小样本检索，确认原文/摘要、定位和版本字段，再放入已获准的脱敏测试材料。

## 2. 在千问办公维护法律连接器

桌面客户端进入“扩展→连接器”维护服务和认证信息；不要将配置 JSON、Token 或本机启动命令写入本仓库。[千问官方连接器说明](https://help.aliyun.com/zh/qwenwork/qw-connectors)

开启连接器后新建对话，再查看工具清单。记录：实际工具名、输入结构、内容类型、原始出处/定位字段、额度或权限错误。401/403需要检查Token及服务权限，不能作为“没有检索结果”；关键词列表并非已取得全文。

## 3. 认证或兼容性异常

按宿主提供的认证流程处理；例如 CourtListener 当前仍待解决登录问题。异常和后续验证状态记录在[接入评估](海外法律数据接入评估.md)，不以本地适配器或本地 MCP 服务作为替代方案。

## 4. 首轮联调输入与通过条件

以下是测试请求模板，不是已运行的案例；方括号内容在测试前替换。

**工具验证：**“使用已连接的北大法宝查询[已知法规名称及相关条款]，列出实际来源、版本/效力信息及取得的原文范围；未取得正文请明确说明。”通过条件是有真实工具记录，输出与已知官方原文可比对，且不把摘要冒充全文。

**非诉工作：**“以LexPrism工作流程审阅[脱敏合同]，按[我方身份、交易目标、适用法、基准日]给出主要风险与修订建议；允许使用已授权数据库，事实缺口与法律依据分开列明。”通过条件是关键建议有事实前提、依据、定位和具体修改，律师能复核。

**证据工作：**“仅根据[脱敏材料包]建立事实时间线与争点—证据矩阵，区分主张、材料记载和已确认事实，标出冲突与缺件。”通过条件是不引入外部事实或把材料缺失判定为事实不存在。

**反馈回归：**“依据[本次律师原始评语]修改上一版，保留评语位置和适用范围；说明影响的主张和段落。”通过条件是只修改受影响范围并记录版本；不能声称反馈已自动训练模型或改动全局技能文件。

此外应测试关闭数据库、错权限、只允许给定材料、新增不利材料、引文定位不存在以及其他法域输入。失败时能明确说明未完成部分，才具备稳定演示基础。

## 5. 保存运行证据

每次联调在`runs/<case_id>/<run_id>/`保存输入版本、技能版本、实际可见模型信息、工具清单/调用记录、输出、未完成项和评审记录；资料保存需符合授权范围。可使用[运行模板](../evals/templates/run.template.json)，把模板占位值替换为事实。没有宿主日志导出能力时保存可获得的操作记录，缺失项标unknown，不能补造调用。

静态校验和ZIP打包只能证明文件格式与结构。只有上述实际运行完成，才能将对应能力标为“千问办公已验证”。
