# LexPrism 工作区维护与恢复

供安装者和执行文件流程的 Agent 使用，运行程序版本为 0.8.0-two-window。首次配置见 [一次性部署说明](一次性部署说明.md)，日常对话见 [律师使用说明](律师使用说明.md)。本文集中说明存储、恢复与升级。

事项选择、可选命名、两个窗口的职责与正式交付统一见 [项目协作规则](../skills/lexprism/references/project-collaboration.md)；具体命令、成果清单及审阅记录格式见 [运行接口](../skills/lexprism/references/project-runtime.md)。

## 存储和备份

| 位置 | 内容 | 维护要求 |
| --- | --- | --- |
| matters | 原件、工作副本、封存版本、意见、确认与发布尝试 | 保留完整历史，只编辑未提交副本和未完成意见 |
| .lexprism | 窗口绑定、输出目录归属、文件名保留记录 | 与 matters 一并备份，恢复时核对对应关系 |
| output | 已审、已确认的正式文件副本 | 不能替代完整档案，不覆盖旧交付 |

发布要求同一授权工作区内的普通目录，以及支持硬链接的文件系统（如 Windows 本地 NTFS）。程序从暂存文件原子发布，不覆盖既有文件；环境不支持时返回失败并保留记录。

## 异常恢复

| 实际状态 | 下一步 |
| --- | --- |
| 未审、需修改、待补、仍在审或缺确认 | 完成对应步骤，不写正式文件 |
| 锁冲突、基线陈旧或校验失败 | 刷新真实记录并核查；不强改状态、删除历史或清除仍活动的锁 |
| 已确认但写入失败 | 解决原因后用同一发布编号重试；条件未变时保留原确认 |
| 文件已写入但登记失败 | 核对该请求的文件名保留记录与指纹后补登记，不重复生成 |
| 交付已登记但 WORK 写入失败 | 用 status 重建索引，保留已登记交付 |
| 名称冲突、跨事项同名或输出归属不明 | 改用经确认的不同名称，不合并覆盖 |
| 版本、文件、名称或有效审阅改变 | 重新预检并取得相应确认；实质修订须新版本及独立复审 |
| 已发布文件丢失或被修改 | 核查原因；不以重复执行发布静默重建 |

已成功请求重复执行只返回原文件链接。保存、确认、文件写入和登记按实际结果分别报告；本地发布不等于发送、签署或送达。

## 升级和验证

使用工作区统一 scripts/document_workflow.py，不自动使用事项内遗留的旧程序。旧 state schema_version=1 和单 pair manifest 保持可读；正式发布前，从旧内容创建带成果清单的新版本并独立复审，不改写旧封存历史或补造字段。

新送审包使用 submission_protocol=2，独立审阅使用 review_protocol=3。程序验证文件和记录完整性，不能认证填写的 actor 或用户原话；真实独立对话和律师确认必须可回查。包检查和合成测试不代表千问导入、Word 页面或法律质量已经验收。
