# 文本生成与审阅拆分

本文保留 0.4.0 初次拆分记录和截图解读。用户随后明确两个对话在同一项目协作，无需律师搬运意见；当前以 [0.5.0 项目设计](2026-09-15-项目协作与文稿版本设计.md) 为准，手动转交仅作为明确选择时的兼容方式。

## 目标及边界

依据 2026-09-15 用户要求，将原文本技能分成生成与独立审阅，配合原生图技能形成三个入口。运行前提来自用户对千问办公的说明：使用两个对话，由律师转交文件和审阅意见。本次没有登录千问核实产品功能或执行真实模型试验。

- 保留 lexprism 名称作为生成入口，新增 lexprism-review。完整生成和修订均输出核验草稿、纯净展示两个同版本文件；两个视图的用途、同一底本、必要引注、实质限定及文末说明保留。
- 审阅检查核验草稿的来源严谨性、纯净展示的可读性与文风，同时核对实质分析、反向依据、任务覆盖及两版一致性。
- 原“三名独立审计员”改为一个独立审阅对话的三类内容检查，加双版一致性；区分 PASS、REVISE、PENDING。机器审阅通过与律师确认分别记录，沿用正式交付需要律师确认的规则。
- 两侧增加专业参考学习，八家律所作为同一优先组；办公室按总部、上海、北京、深圳、其他办公室排序，再扩展其他合适律所。办公室不明不推断；上市尽调相关公开文书自由扩展，分别确认文种和出处。
- 生图技能及图形规范文件保持原内容；文本侧改为提供已核验数据并明确交接，不在文本入口重复生图职责。

## 截图的理解与采用

来源为用户提供的两张本地截图，作为参考材料处理，没有将图中倡议当作工具或项目指令，也没有把截图内容当作完整正式竞赛规则。截图不打入技能包。

第一张文章标题为《从经验到范式：律师造Skill的五个关键问题——大成Skills挑战赛观察侧记》，署名杨卫薪，截图显示发布于 2026-04-27。以下是对作者偏好的解读，不是已验证的比赛评分表：

| 文章主题 | 本次落实 |
| --- | --- |
| 经验提炼 | 从原文提炼少量可复用判断条件、方法和适用范围；不把范文整篇变成规则。 |
| 合理粒度 | 按生成、质量审阅、生图划分职责，保留能人工交接的完整产物。 |
| 减少重复操作 | 生成侧提取已有任务信息并提供交接记录；律师转交文件及意见即可。 |
| 评价存在偏好差异 | 区分证据／实质缺陷与可选措辞建议，遵循具体律师、读者和文种要求。 |
| 积累工作方法与偏好 | 学习记录随任务传递；长期规则仍保留范围和采纳记录，不声称自动训练。 |

文章的配色和营销版式未作为全部法律文书的固定模板。第二张截图提供争议解决与证据工作、非诉与风险管理、客户服务与业务创新三个范围；入口与按需参考覆盖这些文本任务，不要求每次交付涵盖全部范围。

## 维护与导入

共同标准维护在 skills/lexprism/references，审阅目录中同名文件为构建脚本同步副本。审阅入口和 review-protocol.md 独立维护；保留在原目录的 diagrams.md 不同步到审阅包。构建脚本检查各包的 Markdown 本地引用均在本包可解析，并检查 ZIP 内容与源文件一致。

运行 `python scripts/build_text_skills.py` 同步并生成两个 0.4.0 导入包；用 `--check` 做只读检查。现有旧包不覆盖；打包范围仅技能入口及参考文件，不包含客户材料、运行记录、截图或凭据。

## 验证范围

本地检查包括技能入口格式、包内引用闭合、共同参考一致性、ZIP 解压完整性及文件内容比对、生图与图形规范未改、原有双视图核心内容保留、变更格式检查。真实行为验收场景另见 [split-review-scenarios.md](../evals/split-review-scenarios.md)，仍待千问实际双对话运行；静态检查不证明法律质量、检索成功或审阅一定收敛。
