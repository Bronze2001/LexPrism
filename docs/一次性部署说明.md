# LexPrism 一次性部署说明

文本技能：0.8.3-letter-format｜完整包文档修订：docs1｜2026-09-19。面向首次安装者；完成后律师日常只操作生成、审阅两个窗口。

本版更新生成与审阅 Skill 的律师函模板与批注处理规则，并在需要新建事项时提供一次可选命名机会；保留此前海外投资指南和报告段落格式规则。工作流程序仍为0.8.0-two-window，绘图 Skill 仍为0.3.1-lawyer-handoff。

本包包含三项 Skill、三个千问独立导入 ZIP、本地事项与发布程序、项目模板、MCP 脱敏配置、使用说明、验收清单和三页可编辑流程图。不包含客户材料、真实凭据、Python／Node 安装程序或离线 Word 引擎。

## 一次配置顺序

1. 将完整包解压到固定、获授权的本地工作区。两个对话都使用这一目录，不各复制一套。已有工作区升级时先保留完整旧副本，仅更新规则、脚本和模板，不覆盖 matters、output、.lexprism 或私人配置；旧事项用新版程序验证后继续。
2. 从 skill-imports 分别导入名称含“法律研究与文书”“法律文稿复核”的千问导入包（0.8.3-letter-format）；“股权与交易图”仍为 0.3.1-lawyer-handoff。包内该目录的 README 列出确切文件名。完整工作区 ZIP 解压使用，三个独立 ZIP 才是技能导入文件；具体安装入口按当前账号界面与[千问技能说明](https://help.aliyun.com/zh/qwenwork/skills)。
3. 按下文配置 MCP。连接器可在“扩展→连接器→添加→粘贴 JSON 配置”导入；修改连接器后创建新对话使之生效。[千问连接器说明](https://help.aliyun.com/zh/qwenwork/desktop-connectors)
4. 确认宿主能在本工作区读写文件，并调用 Python 3.10+ 执行 scripts/document_workflow.py。文件程序只用标准库。Word 生成与预览使用千问实际文档能力，不能以 ZIP 已解压代替验收。
5. 运行本地部署检查，或让安装对话执行 scripts/deployment_check.py。它检查包文件、完整性和 MCP 模板，不安装服务、不读密钥、不修改千问私有配置。
6. 分别使用下列启动语打开两个真实对话，跑一个脱敏例子，确认版本、完整意见、候选 Word 和正式文件链接确实可在两窗口读取。

## MCP 配置文件

| 文件 | 内容与用途 |
| --- | --- |
| config/mcp-servers.template.json | 全部 15 项参考配置；其中 EUR-Lex 是可选本地服务，不必一次全部启用 |
| config/mcp-pkulaw.template.json | 北大法宝 9 项远程服务，先配置此组 |
| config/mcp-overseas.template.json | 5 项海外远程服务，按业务需要启用 |
| config/mcp-eurlex.optional.json | EUR-Lex 本地服务，单独确认运行环境后启用 |
| config/mcp-catalog.json | 服务来源日期、用途和本版验证范围 |

北大法宝的 `<YOUR_PKULAW_BEARER_TOKEN>` 在目标千问的私有配置界面替换；不把填好密钥的文件放回部署目录或压缩包。不要整体覆盖已有千问配置，按服务名称导入、合并或在界面更新，保留其他连接器。包检查会拒绝含真实 Authorization 值的模板。

远程地址沿用本项目 2026-09-11 的脱敏配置快照，传输字段规范为当前文档示例的 streamable-http。该快照不是本次逐项联网成功的证明；服务商地址、授权及工具能力以目标环境实际返回为准。配置格式、身份验证、工具发现、取得原文和法律质量分别验收。

EUR-Lex 固定候选版本为 0.12.1，其项目元数据列 Node >=24，并提供 npx 可调用入口。本轮核对了[提供方 package.json](https://github.com/cyanheads/eur-lex-mcp-server/blob/main/package.json)，未在目标千问启动此包，也未验证 npm 下载；需要欧盟服务时由安装者确认包可取得及实际启动，不把它当成主流程的必需依赖。首次启动需要网络，不属于离线组件。

## 两个窗口首次启动语

生成窗口：

> 请先读取本工作区 PROJECT.md，使用 lexprism 作为生成窗口。成篇任务按本项目流程自动管理文件和版本。我会提供项目材料与名称；请自行保存和提交，审阅由我到另一个窗口触发。

审阅窗口：

> 请先读取本工作区 PROJECT.md，使用 lexprism-review 独立审阅“〔项目名称〕”的当前送审版本。请绑定生成窗口使用的同一事项，直接读取完整成果、依据及历史意见，不修改送审正文；完成后保存完整意见并告诉我下一步。

将名称替换为实际项目；多个候选时选择明确事项。不要使用同一生成对话换角色冒充独立审阅。宿主没有自动加载项目入口时，首次启动语明确要求读取；后续继续从真实事项记录接续。

## 最小验收

- 两个窗口绑定同一事项；律师不用复制审阅意见或移动文件；未触发另一窗口时正常等待。
- 生成并封存 Word 与核验稿，独立窗口读取相同版本；修订另存新版本，旧版通过不能批准新稿。
- 发布前链接已审候选文件，取得真实律师确认；正式文件与候选一致，旧交付保留。
- MCP 按实际启用项进行工具发现和非敏感样例检索，记录原始返回、原文链接、条款／页段及版本信息。401／403、空结果、仅摘要与取得全文分别说明。
- 关闭连接器、缺关键材料、需要修改或无律师确认时，不把流程说成已经正式交付。

本地自动测试与包检查只证明程序和包结构；千问中的技能路由、实际独立对话、Word 页面和法律质量仍需上述实际验收。日常操作见[律师使用说明](律师使用说明.md)，异常恢复及备份见[工作区维护与恢复](项目协作操作说明.md)。
