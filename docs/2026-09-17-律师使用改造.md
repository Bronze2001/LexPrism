文本技能更新为 `0.7.0-lawyer-first`，绘图入口更新为 `0.3.1-lawyer-handoff`。本轮修改原项目的技能源文件、共同参考、项目模板、用户说明和打包程序。测试2旧输出、已登记事项、千问已安装技能及连接器配置未改写。

## 判断：主要负担在默认执行路径

旧生成入口要求先发现事项、取得独占工作副本、形成完整双文件、提交和登记审阅，即使问题很短也容易进入整套流程。9月16日已经缩短过入口文字，但工作顺序仍然不分任务大小。本轮改变工作量的选择方式，不把继续压缩字数或增加脚本数量当作产品目标。

诊断的参照是测试目录内的三件套，不能直接代表当前仓库。现场核对包括诊断全文、香港事项 v4 正文、RESPONSE、SUPPLEMENT-2、文件清单，以及当前技能、引用标准、模板和运行程序。

## 律师现在怎样使用

| 工作 | 新默认 |
| --- | --- |
| 查一条规则、简短法律答复 | 直接作答，保留依据和关键限定；不建目录、登记事项或生成整套报告。 |
| 短篇事实整理、邮件措辞 | 直接给文字或一个文件，必要来源说明就地附上；单一来源不逐句堆相同脚注。 |
| 起草意见、函件、检索报告、合同审查成果 | 成篇文书优先可编辑 Word，另附必要核验说明；正文中的实质依据与风险继续保留。 |
| 已要求核验稿／纯净稿 | 继续从同一底本交付双视图，不因本轮改造取消已约定的交付物。 |
| 审一份独立文稿 | 直接读取所给正文和原始依据，出一份审阅意见；不要求先初始化或另造第二份正文。 |
| 长期管理版本、并行修改或继续已登记事项 | 才启用原项目程序，版本、冲突、历史和登记规则继续有效。 |
| 画股权或交易结构图 | 提供预览和可编辑文件，默认不展示大段 XML；复用已给主体与关系，不让律师填写 JSON。 |

普通成篇文书的“正文＋核验说明”与旧“双份完整正文”有所区别：说明保存原文定位、主张对应、实际核验及缺口，不重复全文。已有双视图和项目事项的成对文件要求保留。原始证据按实际需要保留，不能把减少文件数量当成删证据的理由。

原文、时间效力、适用性、反向材料、样本非权威、审阅意见必须有依据、允许撤回误报、新版本重新复核和真实律师确认均保留。正式法律交付仍不能由同一对话换角色或生成 Word 文件证明完成；事实校对无需先走整份法律验收。

## Word 与安装边界

Word 输出规则接到宿主实际可用的文档技能／工具，千问已有 docx 能力时直接复用；不新增每案重写的转换程序。要求导出后核对正文、引注、表格和页面；无法生成或预览时如实说明，不把 Markdown 改后缀当 Word。

这次完成的是规则接入，尚未在千问实际生成并预览 Word。也未替律师安装 Python、修改凭据或新增连接器。

共同文本规则仍由生成技能维护，打包时同步到审阅技能，使独立导入包保持自足；不建立额外共享技能目录或跨包相对依赖。千问包在打包时增加双语卡片字段和推荐提问，通用包保留 Codex UI 信息，正文规则一致。新增代码仅用于现有构建程序的宿主适配与包内核验，运行时版本和绘图程序未改动。

本轮沿用已有技能分发方式，没有创建新插件市场、全局配置或新增分诊技能。完整项目包是可选高级包，首页改为律师使用说明，程序命令另置于项目操作说明。
