# 技能精简记录

本轮在原项目将文本技能和完整包由0.6.0更新为0.6.1-lean。用户自行同步测试环境，本轮未读取或修改测试文件夹的技能，也未更新千问已安装技能。

## 判断

现有技能有明显重复和执行入口分散：生成入口重复列研究、自检、阶段状态和双视图，审阅入口又重述协议和通过规则；drafting-review同时写起草标准与完整独立审阅流程；data-and-tools混合概念数据模型、旧状态机、假想工具名称和真实运行文件。

这增加了找到当前步骤的成本，但仅凭长度和一次测试不能确认法律错误由技能臃肿导致。过去观察到的法源过时、审阅误报和项目未登记仍需各自验证。本轮针对可直接确认的重复、歧义和路径错误做精简。

## 现在各文件负责什么

| 文件 | 职责 |
| --- | --- |
| 两个SKILL.md | 当前角色的四步流程，以及有具体触发条件的参考入口 |
| research.md | 原文、基准日效力、适用性、来源与语言等级、反向依据；本轮内容不变 |
| drafting-review.md | 成品正文、脚注、引用记录、双视图与用户编辑同步 |
| review-protocol.md | 审阅四维检查、意见证据、报告和复审执行 |
| review-decisions.md | PASS／REVISE／PENDING、关闭问题、停止与律师确认；本轮内容不变 |
| project-collaboration.md及项目模板 | 找事项、工作副本和真实程序动作、版本历史与登记结果 |
| data-and-tools.md | BRIEF、依据／主张映射、引用快照、RESPONSE及真实review文件的最小记录要求 |

入口明确：只在当前任务触发时加载参考；本对话已读且未变的规则不反复读取；链接不是递归遍历所有文件的要求。这不允许省略原始任务、两份完整文稿或采用依据的实际核验。

## 消除的歧义

1. **第二套审阅结果**：实际程序使用reviews下REVIEW.md和result.json，移除日常规则里另建audit_report.json的建议。旧报告仍保留，不改写历史。
2. **概念模型当运行要求**：移除未实现的Task／Run等全套对象表、假想工具API清单及BLOCKED／UNRESTRICTED_DELIVERY等额外状态机。保留最小事实、来源、主张、执行和反馈记录；G1—G5仅解释历史阶段，不要求另建状态系统。
3. **冻结被误解为不能纠错**：改为“先登记并核验依据，新增或纠错先更新记录再写文稿，保留旧版”。仍要求所有实质引用可追溯，不允许凭模型记忆补法条；完整核验附录与快照可以相互引用，不要求重复记账。
4. **重复审阅指令**：drafting-review专注成品标准，独立审阅执行和结论条件分别留在review-protocol和review-decisions。
5. **项目指令重复法律规则**：模板只保留项目选择、文件协作、历史及实际登记；法律判断由技能负责，避免两处并行维护。
6. **草稿路径错误**：project-collaboration原目录图漏掉files层，已明确使用checkout实际返回的`drafts/<编号>/files/`，所有必交文件保存于该处。

## 保留的关键要求

- 原始问题决定范围，人工样本仅提炼结构与文风；近期新增的法律检索报告标准保留。
- 原文、时间效力、本案适用性三项分开；关键缺口不能由免责声明修复；反向材料、例外、转引及过渡规则保留。
- 完整生成和送审仍有两个文件，共同正文、引注、实质条件与文末说明一致；用户编辑先合入底本，不覆盖历史。
- 审阅也须证据，生成侧可附证据异议，审阅侧确认解决或撤回误报；新稿重新审，旧版通过不继承。
- 项目发现、独占工作副本、正式提交、版本／哈希核对、真实审阅登记及律师确认保留。
- 生图、自主学习、既有文末说明、法源核验主体文件和运行程序本轮未改；各业务清单与翻译／隐私规则保留。
