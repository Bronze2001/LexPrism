## 1. 选型结论

国内首先使用已完整接入且正常使用的北大法宝官方 MCP。海外先使用已配置的 EUR-Lex、eCFR/Federal Register、Lex UK Legislation、Pipeworx US Case Law、Pipeworx Legal 与 overview.legal；CourtListener 官方 MCP、Westlaw 和 GovInfo 按看板中的授权或注册状态推进。不要只用美国判例库覆盖合规与交易研究，也不要把第三方或社区 MCP 的返回直接当作经过版本核验的法律原文。

## 2. 首轮具体接法

### 北大法宝：直连，不重复封装

以[官方完整接入文档](https://mcp.pkulaw.com/docs?doc=mcp-integration)与控制台生成的配置为准，使用Bearer Token。北大法宝现已在千问办公完整接入并正常使用；配置覆盖法规语义检索、法规关键词、法条关键词、案例语义检索及引用纠错等服务。其余服务按实际任务添加，避免一开始暴露大量重复工具。

官方法规关键词服务页面明确存在返回法律列表的能力；列表结果不能自动当成完整法条正文。持续记录真实工具名、参数、返回字段和原文取得方式。[服务目录](https://mcp.pkulaw.com/apis)、[法规关键词服务](https://mcp.pkulaw.com/apis/1948588494288982016)

### CourtListener：先官方MCP，后REST备选

官方地址为`https://mcp.courtlistener.com/`。该服务的总览页面明确将其列为供 Claude、ChatGPT 等 AI 助手直接访问 CourtListener 数据/API 的 MCP；本项目另以用户人工确认“可使用且允许 AI 助手访问”为准。当前阻塞为邮箱登录失败，因此尚未完成本环境接入。交互式宿主可由 OAuth 登录；不能完成浏览器授权的千问办公/后端场景可用个人 CourtListener 账号的 API Token，以`Authorization: Token <token>`连接官方 MCP。登录解决后再测工具发现、一次检索、一次结果/原文获取以及引文检查。免费/会员/商业使用的额度和范围仍按账户确认，不承诺无限免费。脱敏迁移模板与现有替代服务见[《MCP 接入与部署说明》](MCP接入与部署说明.md)。

若千问办公暂不支持该认证流程，可依据[官方REST文档](https://wiki.free.law/c/courtlistener/help/api/rest/v4/rest-api-v47)评估本地MCP适配；不能仅凭协议兼容就宣称直连成功。

### 海外非诉接口：按需求只选一个起步

英国立法、欧盟和美国联邦规章已经分别接入 Lex UK Legislation、EUR-Lex 与 eCFR/Federal Register MCP；Pipeworx 与 overview.legal 已作为美国综合法源和欧盟数据合规的补充服务配置。首次真实任务中，英国侧仍记录版本和原文 URL，欧盟侧保留 CELEX/资源标识符和语言，美国侧记录 eCFR 标题、章节及生效日期；GovInfo 待取得凭据后再纳入。它们可以共享 Source/Passage 输出格式，但不能共享一套未经验证的法域和时效判断。

## 3. 个人开发者注册与 MCP 可行性（本轮结论）

“个人可注册”分为三种，不能混用：①无需注册即可调用；②个人可自助注册并取得凭据；③需用组织订阅、审批或管理员开通。上述数据源的当前结论如下。

| 级别 | 数据源 | 结论 | 推荐动作 |
| --- | --- | --- | --- |
| 已在千问办公接入 | EUR-Lex MCP、Lex UK Legislation MCP、eCFR/Federal Register 社区 MCP、Pipeworx US Case Law、Pipeworx Legal、overview.legal | 六项均已配置；前三项分别服务欧盟与英国立法、美国联邦规章，后三项补足美国判例／综合法规和欧盟数据合规关联 | 完成首个真实样本的原文、版本/生效时间与定位验证；第三方和社区 MCP 另记录提供方、上游法源与返回链接。 |
| 个人账号可测但尚未完成 | CourtListener、vLex 开发者门户、GovInfo | CourtListener 个人账号带 Token 且官方 MCP 同时支持 OAuth/M2M，但当前邮箱登录失败；vLex 可创建 API 用户但法律内容取决于订阅；GovInfo 的 API.data.gov Key 为开发者 Key | 先解决 CourtListener 登录；vLex、GovInfo 仅做注册/凭据层验证，不把试用或 DEMO_KEY 当生产授权。 |
| 公开取文、搜索另审 | EUR-Lex / Cellar | 已接入的 EUR-Lex MCP 不改变基础权限：Cellar REST 公开，EUR-Lex SOAP 搜索可能须注册并审批 | 真实任务中保留 CELEX 和原文来源；需要额外结构化搜索时再按官方流程申请。 |
| 组织授权后才进入 | Lexis、CoCounsel / Westlaw | Lexis 为 B 端 API 订阅；CoCounsel MCP 要现有订阅与账户级启用，官方当前面向 Claude | 不进行个人试注册或绕过授权；由律所/客户经理确认合同、账号和 AI 使用条款后再排期。 |

除北大法宝已经完整接入并正常使用、以及六项海外法律服务已在千问办公配置外，本轮未替团队注册 CourtListener、GovInfo 或商业库账号，亦未记录或保存任何新增凭据。这里的“已接入”不等于已完成每个法源的全文、版本、时效及法律输出验证。

## 4. 商业数据库应该确认什么

普通律师检索账号不等于API凭据，也不自动授予将全文输入千问模型的权限。准备向现有客户经理询问以下内容即可；本轮未代发邮件或提交申请。

- 当前订阅能否开通API/MCP，开发者账号和沙箱如何取得；是否支持第三方千问办公。
- 授权的国家、数据库、正文、历史版本、引证分析分别有哪些；返回原文还是供应商AI报告。
- 能否把内容用于推理、引用、日志、短期缓存、团队评测；模型供应商/区域/保留期有何条件。
- 鉴权、并发、配额、计费、测试额度与故障处理；标准账号和额外产品的权限边界。

CoCounsel官方接口是“启动研究→查状态→取报告→追问”路线，等待时间和报告形式应纳入流程设计，不能映射成即时全文检索。vLex开发者门户首页存在旧介绍，不能据此否认新目录中的API；反过来，也不能将目录宣传当作已获可用凭据。

## 5. 有内容不代表能直接做抓取MCP

英国国家档案馆Find Case Law提供判决访问，但其针对计算分析和相关AI使用的许可规则需按具体用法确认。个人逐篇阅读与批量计算用途并非同一授权范围，适合先核实再作为产品数据源。[许可说明](https://caselaw.nationalarchives.gov.uk/permissions-and-licensing)、[何时需要许可](https://caselaw.nationalarchives.gov.uk/when-you-need-permission)

CanLII现行条款限制系统化下载及相关自动化访问，因此不列入默认爬虫MCP方案；需要加拿大内容时优先寻找原发布机构或获得许可的渠道。[CanLII条款](https://www.canlii.org/info/terms.html)

这不是对所有法域和数据库的穷尽调查。香港也不会因已有一个测试题就被设为必接专用数据源。新增法域依据后续真实案件/评测需求决定。

## 6. 接入完成的定义

“文档确认”→“账号授权确认”→“认证与工具发现成功”→“真实样本可取得并定位”→“错误与时效路径验证”→“律师认可该任务输出”，逐级记录。当前北大法宝达到“已完整接入、正常使用”；EUR-Lex、eCFR/Federal Register、Lex UK Legislation、Pipeworx US Case Law、Pipeworx Legal 与 overview.legal 已达到“千问办公已配置”，其中 Pipeworx／overview 仍需逐项真实任务验证；CourtListener 官方 MCP、Westlaw 与 GovInfo 尚未进入“已接入”状态。本看板和实际测试证据以千问办公内的连接器与运行记录为准。
