## 律师实际操作

1. 生成窗口提出任务、提供材料和项目名称；名称未定时可以先研究和起草。
2. 到审阅窗口说“审阅这个项目的当前送审版本”。该窗口直接读同一事项，不需要复制原稿或意见。
3. 需要修改时回生成窗口说“按完整审阅意见修订并重新提交”，再由律师触发复审。
4. 通过后回生成窗口，核对候选文件、项目名、文件名和交付范围，一次明确确认。
5. 系统将这份已经审阅并确认的候选文件复制到 output，返回正式链接；事项中的旧版、证据和意见继续保留。

此处“自动管理”指对话触发后的本地文件流程。文件保存不会自动唤起另一窗口；模型处理、法源检索及宿主文档功能仍按实际千问能力运行。

## 本地程序与文件约束

- 工作区入口负责识别是否进入项目流程；简短答复不初始化事项。每个真实窗口分别绑定事项，显式名称或路径优先，多候选才询问，不设置供所有窗口共享的全局当前事项。
- 新事项用工作区统一程序管理；matters 保留全过程，output 只存正式副本。旧单 pair 历史可读，正式发布前需新建带成果清单的送审版本并独立审阅，不回填虚构历史。
- 已送审版本只读；修改创建新工作副本和新版本。新稿必须回应继承的阻断问题，关闭、撤回或降级须由实际复审附理由和依据。
- 发布分为准备、律师确认、执行三个动作。准备即固定候选、版本、有效审阅集合、名称和范围；这些内容改变后原确认失效。通过或完成生成都不自动发布。
- 发布前再查当前版本、完整成果、有效独立审阅、必要检查、未完成审阅、确认和目标归属。项目名、文件名检查路径、Windows 保留名及长度，目录和文件不得跨事项合并或静默覆盖。
- 正式副本逐字节复制已经审阅的候选，不在发布阶段重新排版。新版本产生新交付文件；重复执行已成功请求返回原文件，不重复生成。
- 写入失败保留确认，文件写入后登记失败记录待恢复状态；用同一发布编号接续。多附件部分写入可恢复，旧交付丢失或被改不会被静默重建。
- 本地文件管理只用 Python 标准库，要求 Python 3.10+。发布用同一工作区内的原子创建机制；目标应采用支持硬链接的本地文件系统，例如 NTFS，部署验收实际测试写入能力。

实际窗口、审阅记录和律师确认的来源引用由宿主与执行 Agent 如实提供。程序会核对记录与版本的绑定关系，但没有把这些字符串当作身份认证系统；不能伪造来源或用自检冒充独立审阅。

## MCP 与首次安装

部署包包含 15 项脱敏参考配置：北大法宝 9 项、海外远程服务 5 项、EUR-Lex 可选本地服务 1 项；同时提供全量及三个分组文件。远程服务沿用项目 2026-09-11 的配置快照，逐项标记本版未进行真实联网验收。配置模板仅含凭据占位符，实际令牌在目标千问的私有配置界面填写。

连接器安装路径及传输字段按[千问官方连接器文档](https://help.aliyun.com/zh/qwenwork/desktop-connectors)核对。EUR-Lex 候选包固定 0.12.1，环境要求按[提供方 package.json](https://github.com/cyanheads/eur-lex-mcp-server/blob/main/package.json)核对为 Node >=24；本轮未验证 npm 下载或目标千问启动。它是可选项，不阻塞本地文件流程。

一次性部署包提供完整安装资源；首次导入 Skill、填写授权、授予工作区访问和运行脱敏验收仍由安装者完成。它不包含客户文件、真实凭据、Python／Node 安装程序或离线 Word 引擎，不覆盖千问已有私人配置。

## 目标千问的待验收项

1. 导入两个文本 Skill，确认实际路由到正确窗口；明确能读取同一授权工作区及调用本地程序。
2. 跑一次脱敏两窗口往返，确认无需手动复制审阅意见、管理版本或移动文件，且等待另一窗口由律师触发。
3. 用宿主实际文档能力生成、打开并检查 Word 正文、原生引注及页面，复审最终候选，再确认正式副本与候选一致。
4. 按启用的 MCP 逐项验证授权、工具发现、非敏感样例检索与取得原文，分别记录失败、仅摘要和完整原文。
5. 重跑律师函及双视图案例，专业评阅事实边界、引用支持、共同主张、反馈整体闭合及对外文风。此前样本的合同、费率或结论不得补成本案事实。

完成这些实际验收前，只能报告“程序与部署资源已完成，本地检查通过”，不报告千问生产部署、法律效果或真实案例验收完成。
