# 共用审阅判定与问题关闭

生成自检和独立审阅使用同一内容标准，只有另一个实际审阅对话可称独立审阅。普通文件与项目模式共用本判定；G4／G5 是旧记录名称，律师界面使用“待审阅／需修改／待补件／待律师确认／已确认”，不要求填写状态码。

## 判定

| 结论 | 条件 |
| --- | --- |
| PASS 审阅通过 | 所审版本和本任务要求的材料完整，证据、覆盖、文风及适用的一致性检查已完成并符合标准，无未解决的阻断问题和未完成的必要检查。只有一份正文且未要求双视图时，多视图比对可说明不适用；必要证据不能省略。 |
| REVISE 修改后复审 | 输入足以判断，但存在需要修订的实质、覆盖或表达缺陷。 |
| PENDING 待补件／待确认 | 关键材料、原文、适用版本或决定性事实欠缺，使必要判断无法完成。兼有明确错误时同时列出，整体仍为 PENDING。 |

非阻断的可选措辞建议可随 PASS 给出；妨碍理解、遗漏关键条件、错引或违背明确交付要求的缺陷不能作偏好处理。未做完整审阅只给局部结论。无关检查可以有理由地记为不适用，不因缺少无关材料阻断。

“已列缺口”“加了可能／以原文为准”“增加免责声明”都不修复核心证据不足。可删除不必要且无依据的延伸主张，但不能删掉委托必须回答的问题来获得 PASS。来源新旧、规则适用和原文对应分别判断；样本、来源数量和文件哈希不证明法律正确。

评估缺口是否阻断，要指出其影响的受托问题或具体行动。次要细节、范围外事项和不影响限定结论的材料缺失可不阻断；若缺口决定核心资格、成本、期限或建议，则即使已披露也仍待核。只完成“在所给材料内修订与核销”的审阅，可以给该范围的结果，不能登记成整份法律证据检查 PASS。普通记录与项目 result.json 的范围、各项判定和未完成检查须相符，不将仍须完成的必要核验一律推给“律师确认”后清空 unperformed_checks。

## 问题的处理与关闭

生成侧在核验说明中逐项写明“接受并处理／附证据异议／待补件”（已有项目用 RESPONSE.md），附改动位置、材料和原因，不自行宣称审阅阻断已经关闭。审阅侧对指定新版本核对原问题、新文字及证据，记录“仍存在／确认解决／撤回误报”，写明理由并保留稳定编号。

已有项目的结构化记录沿用 OPEN／RESOLVED；“确认解决”和“撤回误报”由审阅侧登记为 RESOLVED，在 resolution 中分别写实际原因及证据。普通文件在意见中自然语言记录即可。已完成意见不覆盖；纠正同版旧结论时另存意见，注明替代对象及理由（项目用 supersedes）。事实／依据包或正文改变时保存新版本，已登记事项须重新提交。

审阅期间发现新版本，当前审阅仍只适用于原绑定版本。下次复审必须读取新版本；可以复用确未受影响的检查，但要说明范围并核查修改对其他结论、引用和双版一致性的影响。生成侧回应、旧审阅 PASS、问题原句消失均不能代替实际复审。

## 停止与交付

下述正式法律交付要求仅用于本次受托法律成果；单纯事实核对或文字校对完成其指定范围即可，不要求律师确认才能给出校对意见，也不声称整份法律文书已通过。

对当前版本 PASS 后停止修订；不因个人措辞偏好无休止退回。存在实质分歧时先复核双方依据，能自主取得的材料继续取得；同一分歧没有新增证据或仅能由律师确认事实／立场时，汇总争点、双方依据、影响和所需裁决，暂停受影响结论，不靠重复润色消除分歧。

每次受托审阅完成约定范围后出一份完整结论并结束本轮。需要新一轮的条件是收到修改稿、相关新材料、具体遗漏／误报证据或用户明确要求扩大检查；不因尚未获律师确认自动追加续查。次数上限不能把未解决问题变成通过。

独立审阅通过与律师确认分开记录。标记正式交付仍需两者覆盖当前版本；未确认时交付标明状态的草稿，并列出律师需要决定的事实、立场或未决事项，没有具体缺项时只记“待律师确认本版”。不把生成 Word、阅读、沉默或时间经过当作确认，不自动设期限、催办或重复生成文件。律师对确切版本的明确确认按原话、日期和范围保存到核验／工作记录；不自行补签名。实质改稿产生新版本并重新检查受影响范围。

记录真实所审文件、版本、检查范围、执行情况及可回查记录。历史对话独立性无法确认时如实说明，不要求不存在的宿主身份接口，也不以自填报告ID证明独立性。同一生成对话改名审阅仍为自检。

受管理项目把审阅、确认与发布成功分开登记，按 [project-collaboration.md](project-collaboration.md) 处理。律师确认绑定已审候选文件、确切版本、名称、路径及交付范围；同版仍有在审、有效 REVISE／PENDING、阻断或必要漏检时不发布。原始完整意见与用户确认消息必须真实可回查，程序只核查绑定关系，不认证消息身份。

文件、版本、名称或有效审阅变化后重新预检并取得相应确认；未变化的技术失败沿用原确认重试。输出只复制确认文件，失败不称交付；正文实质修改另存版本、重新复审和确认，旧交付保留。继承阻断问题须在新稿审阅中明确处理，不能因未列入新报告而自动消失。
