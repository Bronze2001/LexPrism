# 同一项目中的文稿版本与审阅协作

## 协作入口

生成与审阅在同一事项根目录工作；律师只需启动对话和给出任务，已有文件与意见由技能直接读取。先读取项目级 PROJECT.md、事项 WORK.md 及 state.json，再按真实记录找到待处理版本。技能包定义专业方法，项目级指令定义协作职责，配套本地程序负责保存快照、检查版本和登记状态，三者共同使用。

项目提供 document_workflow.py 时，按其 --help 调用；CLI 参数由 Agent 填写，不要求律师操作。技能 ZIP 本身不包含该运行层，也不假设宿主已安装。没有共享目录或脚本执行能力时披露缺口，不能宣称项目协作已配置；仅在用户选择后采用手动文件交接兼容模式。

## 文件约定

```text
事项根目录/
  AGENTS.md / PROJECT.md       项目级指令
  WORK.md                     当前工作索引，程序生成
  state.json                  当前版本与审阅登记，程序维护
  inputs/                     本案原始材料，按授权保存
  drafts/<工作副本编号>/        各生成对话独立编辑
    BRIEF.md                  当前任务事实、范围、来源限制与偏好
    verification.md 或 .docx  核验草稿视图
    clean.md 或 .docx         纯净展示视图
    evidence/                 对应来源快照、片段及必要材料
    RESPONSE.md               变更说明与逐项回应
  versions/v0001/             一次成对提交；历史不覆盖
    manifest.json             基线、作者标识、完整文件清单及哈希
    files/                    本次双视图、任务说明、证据与回应
    CHANGES.md                与上一版本的差异；文本可自动比较
  reviews/r0001/              一次审阅工作区
    result.json / REVIEW.md    未提交时可编辑
    final/                    完成后封存的意见与检查结果
```

文件后缀随任务选择，两个视图必须能分别读取，不能只生成一份混合正文。哈希只证明文件是否变化，不证明法律结论。Word 原生修订或另出的差异文档可作为辅助，独立审阅记录仍是完整意见依据；Markdown 行号不是 Word 页码。

## 提交与复审

1. 生成侧创建独占工作副本，记录当前基线；从项目读取当前版本、原始要求和相关审阅报告。修改底本并同步双视图，将对应证据与逐项回应一并保存。
2. 提交时复制到新 versions 目录，保留文件清单、哈希、基线、实际对话标识和时间。程序检查基线仍是当前版本、两份必交文件及任务／回应记录存在；成功后登记待审。它不判断两版法律含义是否一致。
3. 审阅侧启动后直接发现待审版本，固定读取该版本。意见单独保存在 reviews；形成报告后检查文件未在审阅期间变化，登记结果。
4. 生成侧下一次启动，直接读取相关版本的完整意见及未解决问题，逐项处理并提交新版本。审阅者负责确认问题真正解决，生成者只报告处理结果。
5. 当前版本所有已完成审阅无阻断且无未完成的必要审阅时才可显示审阅通过。旧版本的 PASS 只属历史；新提交默认待审。基线冲突、文件被外部改动或缺件时不继续写通过状态。

写入项目不会自动启动另一个对话。当前部署由律师启动生成／审阅；每个已启动对话应自动读取文件、完成本职责并写回。宿主另有调度能力时可以增加唤醒，但不能仅凭提示词宣称自动执行。

## 独立意见定位

每个问题记录：稳定编号、目标版本及文件、章节／稳定段落标识、原句 exact、前文 prefix、后文 suffix、类别、是否阻断、依据、建议及解决条件。原句重复时用上下文消歧；新版本段落拆分或文字变化时重新定位并记录新旧关系。匹配不唯一时保留待定位，不自动把问题标已解决。

审阅报告完整保存，包括核验过程、工具结果定位、学习参考及未执行事项。结构化检查结果含 evidence、coverage、prose、views 四维 PASS／REVISE／PENDING、阻断问题和未完成检查。实际法律判断与独立性仍由真实对话和记录支撑；actor 名称本身不证明不同自然人或不同模型。

原有 [manual-bridge.md](manual-bridge.md) 中的质量与停止条件继续适用，其手动转交部分仅为用户明确选择时的兼容方式。项目模式下通过共享文件交接，不要求律师复制审阅意见。
