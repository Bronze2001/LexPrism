# 两窗口共享事项与正式交付

用于已配置两窗口管理的工作区、已有登记事项或明确要求版本管理的任务。该工作区内成篇任务由 Agent 自动建档；简短答复不建档，其他环境的独立文件按 [file-delivery.md](file-delivery.md)。律师手动触发两个窗口；目录、命令和记录由 Agent 处理，不让律师执行或搬运材料。

## 每次启动先定位

读取授权工作区 PROJECT.md，使用工作区统一的 scripts/document_workflow.py。先采用用户明确事项路径或名称，否则沿用本窗口绑定；未绑定时在工作区根与直接 matters 子目录查登记元数据。唯一候选仍须匹配任务，多候选无法区分才询问。两个实际对话分别绑定同一事项，不依赖全局“当前事项”。

成篇新任务确无事项时由生成侧创建；明确另起业务事项才使用新建动作。创建前按下节提供一次可选命名机会，不先创建再补问。审阅窗口只选择已有事项。读取所选 PROJECT.md、WORK.md、state.json、所指完整版本和意见，再读任务原件。程序验证真实文件，WORK 仅是可重建索引；读取故障或损坏历史不等于没有事项，不跨客户读取正文寻找匹配。

具体命令及数据模板见 [project-runtime.md](project-runtime.md)，执行前核对实际程序帮助。旧事项使用工作区新版程序验证并继续；不重写旧版本和旧意见，新程序不自动覆盖事项中的历史程序副本。

## 新建前可选命名

已经判断本次需要新建事项、且用户尚未在本轮或上下文给出名称时，由生成侧简短询问一次：“这个项目想叫什么名字？也可以暂不命名，我会按默认规则建档。”用户已给名称则直接沿用；继续已有事项、简短答复、维护任务和审阅窗口不触发这次询问。

先给用户合理的回应机会，期间可继续不依赖事项创建的材料整理和研究。用户表示跳过、回复中未提供名称，或已有合理回应机会仍未命名时，按原规则自动生成内部编号并继续，不反复追问、不把命名作为必填审批，也不把自行拟名写成用户已确认。无异步询问能力时，在正常对话中给出这次命名机会，收到后续回复后按是否提供名称继续。

有名称时随创建记录项目显示名；没有名称时不传空白名称或占位名称，保留现有默认建档方式。事项目录仍由程序生成，名称不直接用作路径，也不因此改名或合并已有事项。提前命名不代表同意正式交付；发布时沿用名称并按原规则确认本版、文件和范围，已给且未变的名称不单独重复追问。

## 生成、送审和独立复审

生成侧取得独占工作副本，在返回的 files 目录保存 BRIEF.md、RESPONSE.md、证据及成果清单。每项受管理成果登记完整核验稿和纯净稿；备忘录与律师函属于不同成果，不互相充当双视图。同成果检查实质一致，不同成果检查共同事实、条件及行动相容性，见 [drafting-review.md](drafting-review.md)。

送审前固定候选 Word 并完成必要内容与页面检查；程序将整组材料封存为新版本。核对成功结果后返回正文链接，提示律师去审阅窗口开始审阅。保存文件、内容完成与登记成功分别说明。

审阅侧固定本版，读取所有成果、任务、证据、旧意见和修改回应，按本窗口审阅协议执行。记录完整意见、真实范围、独立对话定位与必要页面检查。只做局部检查不能登记成整包验收。

生成侧直接读取完整意见，协调反馈目标并修订全稿及相关成果，另存新版本，不自行关闭问题。审阅侧实际读取新稿并处理继承问题，允许有据撤回误报，核销后仍通读全稿。旧版 PASS 不批准新稿。判定与停止规则统一见 [review-decisions.md](review-decisions.md)。

## 通过后办理交付

律师回生成窗口要求交付时，预检最新版本、完整成果、有效独立审阅、阻断与必要检查及是否仍有在审。链接已审候选文件，集中确认尚未确认的项目名、文件名及本次版本和范围。内部编号自动生成；名称不阻塞研究和起草。已确认且未变化的名称不重复询问。

记录律师的真实原话和可回查消息／来源，绑定发布请求中的版本、文件指纹、名称与目标。读过文件、沉默或经过时间不是确认；程序记录和 actor 字符串不证明真实授权或独立身份。缺宿主身份接口时如实说明记录边界，不补造认证。

记录确认后才发布。程序在写入前重新核验门槛，仅复制已审、已确认的纯净候选文件，不改写正文或重新转换格式。默认 output/<项目名>/ 只放一个主成果；明确要求附件时一起纳入清单与确认。核验、证据、审阅和内部说明留在 matters。

名称明显规范化时随确认告知。跨事项同名、归属不明目录或已有文件不合并覆盖。成功才返回正式文件链接；失败保留确认和历史，说明“已确认，尚未成功发布”或“已写入，登记尚未完成”。条件未变时用原发布请求重试，不重新确认或改正文；版本、文件、名称或有效审阅改变则重新预检与相应确认。

发布后实质修改从旧版建新副本，重新送审、审阅、确认并新增交付文件，保留旧交付及历史。正式发布只表示本地副本生成，不自动发送、签署、盖章或送达。

## 运行边界

只编辑未提交副本及未完成审阅；遇基线推进、锁冲突或校验失败先核查，不强改状态或删历史。已有事项缺程序时另存未登记草稿，说明缺口，不假称送审或发布成功。另一窗口无共享能力时才按 [manual-bridge.md](manual-bridge.md) 处理，不要求重复提供已可访问的文件。

图形按需使用 drawio-diagram，随本版成果保留；文本通过不代表图形或页面完成核验。本地档案管理不代表模型推理和数据库调用全部离线。
