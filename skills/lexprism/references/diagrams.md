# 法律流程图与架构图规范 (Legal Diagrams Reference)

本参考为 LexPrism 在非诉与诉讼业务中生成专业图表（股权架构、交易步骤、资金流向、案件事实时间线与证据链）提供设计原则、配色规范与数据交换标准。

> [!TIP]
> 本项目已提供高度模块化、独立的专业绘图 Skill：`drawio-diagram`（位于 `skills/drawio-diagram/`）。包含实务模式库、色彩系统、几何排版及渲染核验四大参考规范。具体绘图操作可直接遵循该独立 Skill。

---

## 适用场景与业务定位

在法律工作中，“一张图胜过千言万语”。当任务涉及复杂主体关系、多步骤交割或密集时间线证据时，LexPrism 应当主动或按要求提供图表化交付物：

| 业务领域 | 核心图表类型 | 适用场景与核心价值 |
| :--- | :--- | :--- |
| **非诉·公司与证券** | **股权穿透与控制权架构图** | 上市核查、实际控制人认定、员工持股平台 (ESOP) 穿透、红筹/VIE 境外架构重组。 |
| **非诉·并购与投融资** | **交易步骤与交割流程图** | 并购签约、前置审批 (反垄断/行业前置)、共管账户资金划转、工商登记与交割先决条件 (CPs)。 |
| **争议·事实查明** | **案件事实时间线图** | 密集合同履约过程梳理、违约节点确认、不可抗力事件发生时点、诉讼时效起算与催告。 |
| **争议·庭审与举证** | **争点要件与证据链推导树** | 诉讼请求 → 法律构成要件 → 待证事实 → 支撑书证/物证 → 证明力漏洞与对方抗辩反驳。 |

## 法律图表规划与“三问原则” (Anti-Decoration Rule)

对标严格的专业工程与学术规范，**图表绝非为了“视觉美化”，必须且仅能用于实质法律论证（Figures should support the argument, not serve as decoration）**。

在生成任何图表前，Agent 必须明确回答以下**三问**；若无法确切回答，则严禁生成冗余装饰性图表：
1. **支持什么主张？(What Claim?)**：明确图表支撑的具体法律主张或事实认定（如：证明张某某直接与间接合计控制 68.5% 表决权；证明 2025-06-14 构成实质性违约起点）。
2. **依据什么来源？(Which Source?)**：明确图表的数据与关系溯源至哪份冻结文件（如 `frozen_citations.json#CIT-001`、工商内档切片、银行加盖业务章对账单）。
3. **位于交付文书何处？(Where in Delivery?)**：明确该图最终嵌入在交付报告、意见书或起诉状的哪个章节编号下。

## 法律图表四级分类管理体系 (Four-Tier Classification)

依据使用场景与法律严肃度，将图表划分为严格的四级体系：

| 图表级别 | 分类定义 | 准入与交付边界 | 典型样例 |
| :--- | :--- | :--- | :--- |
| **Type 1: Diagnostic** (办案推演/诊断图) | 律师办案或 Agent 内部辅助推演、线索发掘的临时工作图 | **严禁包含在正式客户交付物中**，仅留存于内部办案备忘录 | 案件涉案主体推测关联图、尽调未核实假设推演图 |
| **Type 2: Comparison** (方案比选/策略图) | 针对备选商业架构、重组路径或诉讼方案的多维度对比图 | 可选列入法律意见书正文，供客户与合伙人战略决策参考 | 资产收购 vs 股权收购交易路径图、诉讼保全 vs 仲裁保全流程比选 |
| **Type 3: Core Delivery** (正式交付核心图 ★) | 直接支撑正式文书重大事实认定、交易交割或法律构成的核心图表 | **必须经过 [G4 👤: 律师裁决门禁] 人类律师签署确认**方可交付 | 拟上市主体股权穿透架构图、并购交易步骤与交割流程图、违约事实时间线图 |
| **Type 4: Appendix** (附录证据图) | 供正文索引引用的详尽证据链展开图、多层级分支图或复杂流水图 | 作为法律意见书附件或法庭举证材料附录交付 | 30家下属子公司完整展开架构图、数千笔银行资金划转完整穿透流水图 |

## 法律图表前置计划契约 (`diagram_plan.json`)

在正式绘制任何复杂图表（尤其是 Type 2/3/4）前，Agent 必须在 `[G3: CLAIMS_MAPPED]` 阶段编制图表计划，确立形式化契约（模板参考 `evals/templates/diagram_plan.template.json`）：
- 登记 `diagram_id`、`type` (Type 1~4)、`three_questions`（支持的主张、依据切片、嵌入位置）；
- 标记 `lawyer_signoff_required`：所有 Type 3 图表该字段强制为 `true`，未经律师确认禁止交付；
- 记录 `render_check` 状态。

## 律所专业商务视觉与色彩规范

图表必须具备清晰严谨的视觉层级，严禁使用杂乱、刺眼的非标准配色。本系统重点推荐并支持两大顶级实务视觉风格（详见 `skills/drawio-diagram/`）：
1. **🌟 风格 A：典雅藏青 · 涉外跨境风 (Deep Prussian Navy)**：全图冷调深海藏青（`#163854`），点状跨境法域分隔虚线（`#4A5568`），中英双语卡片排版，支持外资限制协议控制与名义代持架构；
2. **💎 风格 B：清爽冰蓝 · 现代并购变动风 (Crisp Ice Blue)**：出资层清透冰蓝大圆角胶囊（`#DDF1FC`），标的主体海洋蔚蓝大卡片（`#0284C7`），横向受让虚线 + 动态持股变动标记（`0 → 30%`、`90% → 60%`）。

经典通用多维色盘标准如下：

| 元素分类 | 建议填充色 (`fillColor`) | 边框线条色 (`strokeColor`) | 文字颜色 (`fontColor`) | 适用对象说明 |
| :--- | :--- | :--- | :--- | :--- |
| **核心主体 / 标的发行公司** | `#163854` / `#0284C7` / `#1B365D` | `#0F293D` / `#0369A1` | `#FFFFFF` (加粗) | 控股公司、涉外实体、协议受让核心标的。 |
| **顶层股东 / 投资人 (冰蓝)**| `#DDF1FC` (清透冰蓝) | `#B3DDF2` | `#163854` | 并购受让方、创始人团队、其他股东胶囊卡片。 |
| **境外合作方 / 当地自然人** | `#1D5174` (深石青色) | `#153E5D` | `#FFFFFF` | 境外当地参股股东、名义代持人。 |
| **普通下属公司 / 关联履约方**| `#EDF2F7` (素雅浅灰白) | `#CBD5E0` | `#2D3748` | 全资/控股运营子公司、履约主体。 |
| **先决条件达成 / 有力书证** | `#2E7D32` (合规深绿) | `#1B5E20` | `#FFFFFF` | 已经满足的交割条件、已固化的原件证据。 |
| **违约风险 / 争议焦点** | `#E53E3E` (警示红) | `#9B2C2C` | `#9B2C2C` / 白 | 违约事件节点、未决重大诉讼、对赌回购触发点。 |
| **律师核查备忘 / 风险提示** | `#FEFCBF` (淡黄便利贴) | `#D69E2E` (虚线) | `#744210` | 经办律师特别提示、闭环校验与未决尽调缺口。 |

## 图表输出规范与双轨交付标准

LexPrism 支持两种互通的标准交付格式：

### 1. 原生 `.drawio` XML 格式（正式业务交付物）
* **特点**：包含精确的几何坐标、节点对齐、正交连接线、分阶段泳道与专业律所配色。
* **必备要素**：
  1. 必须带有明确的**图表主标题**与**法律基准日 (As-Of Date)**。
  2. 股权线必须标明**持股百分比**与**出资形式**。
  3. 交易流向线必须标明**顺序编号**（如“步骤 1”、“步骤 2”）。
  4. 底部或侧边附带 **【经办律师核查备忘卡片】**，提示关键法律风险与核查要点。
* **交付方式**：生成 `.drawio` 文件保存于对应案件成果目录，并可通过 `tools/drawio/index.html` 自由拖拽微调及无损导出 PNG/SVG/PDF。

### 2. Mermaid 文本格式（即时沟通与 Markdown 预览）
* **特点**：纯文本轻量语法，适合在初稿沟通中快速理清步骤脉络或嵌入报告正文。
* **交付方式**：使用 ````mermaid` 代码块，并可通过本地 `tools/drawio/index.html` 的“⚡ 导入 Agent 代码”窗口一键转换为原生可编辑矢量图。

## 门禁体系下的图表渲染核验清单 (Render Check)

在五大门禁中，**“核验渲染后的图形成品，而不仅是看绘图代码”**。在 `[G5: CITATION_AUDITED]` 审计门控中，独立三审计员必须逐项复核以下清单：

### 1. 几何排版与视觉可读性 (Visual Clarity)
- [ ] **无文字截断与溢出**：节点尺寸充分，标题、主体全称、持股比例无截断或跑出边框；
- [ ] **无文字与线条重叠**：连接线采用正交折线或适度圆角，避开节点文本，标签无重叠遮挡；
- [ ] **字号层级清晰**：主体名称（12~14px 加粗）、说明文字（10~11px），在 100% 比例下清晰可辨；
- [ ] **灰度与黑白复印友好**：不同性质的节点即使经过黑白复印或黑白打印，依然可通过边框粗细、虚实线与灰阶明度清晰区分。

### 2. 法律数据与依据一致性 (Data & Citation Consistency)
- [ ] **数值 100% 闭环**：股权图上所有股东持股比例之和必须严格匹配 100%（或明确说明未穿透部分的比例）；
- [ ] **日期与序号 100% 溯源**：时间线图上的每一个关键违约日、催告日、交易交割步骤，必须在 `frozen_citations.json` 中有对应的原始证据条目支持；
- [ ] **严格区分主张与裁判**：严禁在图表中将“原告单方主张的事实”直接标记为“法院认定事实”，必须使用明确限定词。

### 3. 自动化核验工具辅助
在交付前，可直接在终端运行 LexPrism 提供的轻量化自动化核验器：
```bash
python scripts/verify_diagram.py [path_to_diagram.drawio]
```
脚本将自动扫描 XML 语法、法律基准日声明、律师备忘卡片及律所色盘白名单，只有全绿（`[PASS]`）方可签发最终交付物。
