# Draw.io 法律流程图与架构图渲染核验清单 (Render Check)

## 核心质控铁律 (Core Quality Invariant)

> **“代码生成成功或 XML 语法合法，绝不代表渲染结果合格 (Code execution / XML validity != Render verification)。”**

在正式向客户交付或提交庭审/监管申报前，必须逐项审查渲染后的实际矢量图视觉与数据一致性，阻断任何低级失误。

---

## 逐项核验清单 (Checklist)

### 1. 几何排版与视觉品质 (Visual & Layout Quality)

- [ ] **现代大圆角与无文本溢出 (Capsule Cards & No Clipping)**：
  各主体卡片必须具有圆润平滑的流线弧度（`arcSize=16~22`），主体中英文法定全称、出资说明完全包裹在节点内部，严禁出现文字挤压边框或 `...` 截断。
- [ ] **总线式汇流对齐 (Tee / Bus Orthogonal Routing)**：
  同一层级多股东持股线或母公司向下分发线，必须汇流进同一平直总线，严禁杂乱交叉折线横穿主体。
- [ ] **跨境法域虚线清晰规范 (Cross-Border Jurisdiction Divider)**：
  若属于跨境投资或海外设厂，画布必须横向穿过点状虚线（`dashPattern=2 3;`），且左侧具备清晰的境内（如 `中国 China`）与境外（如 `印尼 Indonesia`）法域名称标注。
- [ ] **高雅统一色盘 (Approved Palette Whitelist)**：
  采用典雅普鲁士藏青色（`#163854`）或清爽冰蓝色（`#DDF1FC` / `#0284C7`），严禁使用刺眼杂色或未批准的非标色号。

---

### 2. 法律数据与交易逻辑闭环 (Legal Data & Closure)

- [ ] **持股比例 100.00% 数学闭环 (Mathematical Closure)**：
  - 静态持股：同一标的的直接股东比例相加必须严格闭环为 100.00%（如 `88% + 12% = 100%`）；
  - 动态变动：若标注交易前后跃迁（如 `0 → 30%`、`90% → 60%`、`10%`），变动后的最终比例之和必须严格闭环为 100.00%（`30% + 60% + 10% = 100%`）。
- [ ] **控制权定性准确区分 (Equity vs. Contractual Control)**：
  对直接持股标注确定百分比（如 `100%`）；对外资准入限制业务或协议控制架构，标注 `控制 Control` 并清晰呈现境外当地代持人/合作方的接入分支。
- [ ] **收购动向线箭头逻辑一致**：
  横向受让虚线必须由收购方指向转让方（或标的），并明确标注受让份额（如 `Acquire 30% of the shares`）。

---

### 3. 法定结构要素完备性 (Mandatory Structural Blocks)

- [ ] **主标题规范**：明确标明项目性质、交易形式或架构类型。
- [ ] **法律基准日 (As-Of Date) 完备**：清晰注明“基准日：XXXX年XX月XX日”或英文“As-Of Date”。
- [ ] **【经办律师核查备忘卡片】完备**：画布底端固定锚定柔和淡黄便签卡片，阐明控制权认定、数学闭环证明与待办尽调/审批要点。

---

## 自动化静态合规核验 (Automated Static Verification)

在交付前，在终端执行自动化审计脚本：

```bash
python scripts/verify_diagram.py path/to/diagram.drawio
```

核验器将自动执行：
1. **XML 语法合法性**与图形节点完整性；
2. **基准日声明识别**（检测 `基准日` 或 `As-Of` 关键字）；
3. **经办律师核查备忘卡片识别**（检测 `核查备忘`、`律师提示`、`风险防控` 或 `Memo` 关键字）；
4. **律所色盘白名单核验**（拦截未经批准的非标准配色）；
5. **法域与节点健康度初筛**。

只有当终端打印 `[PASS]` 且人工复核视觉无重叠时，方可正式签发交付。
