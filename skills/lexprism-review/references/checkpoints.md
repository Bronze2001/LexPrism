# 成篇文稿的阶段监控

用于成篇报告、复杂文稿或用户明确要求监控的任务。简短答复、事实校对和少量润色不启用整套节点。节点用于尽早发现会改变方向的问题；不是新增审批流程，也不替代独立审阅。

## 三个检查时点

| 时点 | 必须看清什么 | 留下什么 |
| --- | --- | --- |
| 范围形成后，展开研究前 | 谁委托、谁实际实施受规制行为；客户自身资格、服务对象义务与平台要求是否分开；主要分支和决定性未知事实是什么 | 本轮问题及业务边界、待确认事实、继续研究的分支。已有明确要求直接沿用，不重新访谈 |
| 关键依据取得后，成篇起草前 | 影响准入、成本、期限或核心建议的主张，分别有何原文、现行性与适用性支持；同源转载、更新线索和冲突是否处理；失败的是获取路径还是确实缺依据 | 核心结论可写到何种程度，哪项只能写待核问题；余下检索是否值得继续。优先补会改变答案的缺口，次要细节可以留待专项核实 |
| 完稿送审前；实质修订后重查受影响范围 | 独立通读纯净稿的摘要、分析、结论、行动及脚注；条件和确定程度是否一致；客户执行动作与团队补查工作是否分开；登记版本与交付文件是否对应 | 本版完成范围、仍影响使用的缺口、实际未做检查及下一步。双视图文字一致不能替代这些判断 |

生成侧在已有核验说明或工作副本中记录，每点通常一小段即可：**时间／所涉版本或工作副本—检查对象与证据位置—发现—处理或保留—下一步**。已有引用表直接指向对应项，不复制整套证据，不默认增加三个附件或新的状态文件，不手改程序生成的 WORK.md。

用简短进度说明向用户呈现会影响方向的发现。默认完成检查后继续；只有关键事实、立场或依据确实无法自行确定时，提出具体缺项并暂停受影响结论，同时完成其余已授权部分。用户明确要求在某节点等回复时才将该节点作为暂停点；没有回复不等于同意。上述是 Agent 执行约定，不代表宿主已具备自动暂停或唤醒功能。

## 审阅与复盘

审阅侧核对节点留下的证据和实际文稿，缺记录本身不自动成为法律缺陷。没有当时记录的历史任务，只能做明确标注的事后复盘；不补写成当时已运行的监控点，不凭当前安装版本推断历史已加载规则。

复审先处理原意见，再检查受影响主张在各处的完整表达。对整份成品给结论时，仍须通读纯净稿；未受影响的原文核验可以复用并说明依据。实质缺口不能因已写入附录或改名“固有边界”而关闭，判定遵循 [review-decisions.md](review-decisions.md)。

评估节点是否有效，看它提前发现了哪些范围偏差、无依据建议或版本变化，以及是否减少后段返工；不要以节点数量、来源条数或自填 PASS 衡量质量。
