# 手动交接兼容与共用审阅判定

**当前默认是同一项目协作**，按 [project-collaboration.md](project-collaboration.md) 直接读写共享文件，不要求律师搬运意见。本文件的手动转交步骤仅在用户明确选择非共享环境兼容方式时适用；质量判定、问题处理和停止条件仍为两种模式共用。没有共享目录不自动授权改变用户指定的协作方式，应明确所缺能力。

## 最小交接

律师把同一版本的**核验草稿视图、纯净展示视图**交给审阅对话。生成侧将下列信息放在核验草稿的交接区，已有信息直接提取，不让律师重新填表：

- 任务标识、原始请求及后续有效要求、读者／立场、文种、法域、法律基准日。
- 来源模式和隐私限制、事实前提、指定样式／偏好及参考学习记录。
- 底本版本、两份文件实际名称及各自版本；有真实哈希计算能力时附哈希，未计算不编造。
- 对应来源快照、原文片段、精确定位和授权内可访问的原始材料。快照可附文件或内嵌核验附录；两份视图始终是必交核心，不限制补充证据附件数量。
- 当前缺口、本轮变更、上轮完整审阅意见及逐项回应（初稿除外）、已有律师确认的原话与所涉版本（如有）。

另一对话无法访问前一对话附件或本机路径时，提供授权内必要附件／原文；不能只留“见上一对话”或不可访问路径。摘要不能代替逐字核对的原始材料。材料不足时先完成可做检查，整体待补件，不能通过。

## 审阅维度与结论

独立于生成的审阅对话检查：核验草稿的引注与实质分析、反向材料与覆盖、纯净展示的文风与可读性，以及双视图一致性。这里是**一个审阅对话执行多个检查维度**，不宣称三个独立 Agent 或不同模型一致同意。

| 中文结论 | 状态 | 使用条件 |
| --- | --- | --- |
| 审阅通过 | PASS | 两份同版本文件已完整检查，实质证据及适用性符合标准、关键覆盖无遗漏、表达满足明确读者／文种要求、两版一致；没有未解决的阻断问题或未完成的必要检查。 |
| 修改后复审 | REVISE | 有可定位缺陷；列清所需修改和复审条件。 |
| 待补件／待确认 | PENDING | 文件缺失／不可读、关键原文未取得、事实或范围待确定，必要检查无法完成。 |

三类内容检查和双版一致性分别记录 PASS／REVISE／PENDING；全部 PASS 才能整体 PASS。兼有缺陷和证据不足时保留全部问题，整体 PENDING；输入足够但有缺陷时 REVISE。未做完整审阅只可给局部结果。

已有依据、带真实适用条件的结论，不必等商业风险全部消失才可通过。但事实缺口决定用户要的结论、关键法源未取得或必要检查未完成时，不能用“可能”“附保留通过”掩盖。需要缩小交付范围时由用户明确调整，再对新范围双视图复审。

区分阻断问题与可选偏好建议。当前文件已满足交付要求时，非阻断的标点／措辞建议可随 PASS 列出；妨碍理解、违反明确文种要求或改变法律含义的表达问题必须修订。不为迎合单一审阅者的措辞习惯反复退回。

## 返回生成与复审

审阅输出可直接转发的意见：问题编号、视图与页码／章节／原句位置、类别、是否阻断、依据与原因、要求如何改、如何判定解决。无真实页码则用标题及短原句定位。

生成侧逐项记录“已修改／补充依据／说明不采纳理由／待补件或裁决”，提供对应新位置和版本。不同意审阅意见时给依据，不自行关闭问题；审阅侧复核，仍冲突则交律师决定。律师可改变范围或表达偏好，但不能让模型把未核验原文标为已核验。

生成侧修改底本后重出两份完整文件。审阅侧核对实际修改、受影响证据和段落，再比对两版一致性，不能只看“已改”声明。新版本只沿用有证据证明未受影响的检查结果，说明沿用范围；无可比较旧版则重新检查。事实、法源、读者或范围变化时扩展审阅。

审阅侧默认输出意见，不静默改送审文件再批准自己的改稿。即使给出替换句，也交生成侧落实后复审。纯展示切换且内容未变可沿用状态；文字或文件变化须确认影响，旧 PASS 不能自动覆盖新内容。

## 停止与交付状态

对当前成对版本给出 PASS 后停止修订循环。缺件或冲突时交回明确待办，收到实际补充／修订后继续，不假装两个对话能自动无限互传。

PASS 针对列明的任务、版本、两份文件和检查范围。记录实际审阅回复／可导出对话记录及输入版本；自填报告 ID 不证明独立运行。历史意见的独立性无法确认时标“独立性未确认”；当前确为单独审阅对话时按实记录，不要求不存在的宿主证明接口。同一生成对话改称审阅角色仍属自检。

**G5 审阅通过**与**G4 律师确认**分别记录，先后均可；正式交付仍要求两者覆盖当前版本。审阅通过但律师待确认时标“审阅草稿（审阅通过，待律师确认）”。正式交付仍保留适用前提、必要引注和文末说明；“纯净”只改变展示，不改变风险和状态。
