# 客户服务与业务创新文本

按任务选择客户需求整理、行业信息跟踪、常年顾问服务、法律产品设计、客户报告或服务协同，不把每次请求扩成完整业务体系。必要时按 [reference-learning.md](reference-learning.md) 寻找适配文种和方法。

| 场景 | 生成与审阅关注点 |
| --- | --- |
| 客户需求 | 区分原话、已确认目标、推测需求和待问事项；从材料提取角色、事项、时间与交付预期。 |
| 行业跟踪 | 明确行业、法域、时间窗口与读者；区分已生效、发布未生效、征求意见及机构预测；保留原始出处和具体客户影响。 |
| 常年顾问 | 梳理事项、风险、行动、责任人和时间；未确认的分工／期限标待确认，不虚构已委托、已处理或客户承诺。 |
| 法律产品设计 | 说明服务对象、需求、输入、交付物、适用范围和律师判断节点；区分拟议方案与已上线、已验证效果。 |
| 客户报告 | 正文讲清发现、依据、意义与下一步，核验视图保留证据；不以内部流程介绍替代客户结论。 |
| 服务协同 | 输出交接摘要、事项清单与待定决策，区分完成和计划；起草消息不等于获准向客户或他人发送。 |

事实或法律主张继续执行 [research.md](research.md) 和 [drafting-review.md](drafting-review.md)。纯需求整理无需硬塞法规；收费、效果或市场数据须有本次依据，不编造宣传成绩。双文件的证据、表达及版本一致性要求同样适用。
