# 文件协作与律师交付

起草、修订或审阅独立文件时读取；简短答复不需要本文件。使用当前对话与授权目录已有材料，不以安装项目工具、建立台账或律师填写技术字段为前提。

已配置两窗口管理的工作区内，成篇任务按 [project-collaboration.md](project-collaboration.md) 自动管理事项；本文件用于普通文件及共用格式处理。已有登记事项不降级为无历史的独立文件。

## 文件怎么放

用户给出路径就沿用。否则在当前授权工作区为本次文稿选一个清楚的成果位置；没有本地文件能力时在对话交付可复制内容并说明限制。不要为了确定文件夹名、事项编号或技术模式中断起草。

正式成篇文书默认提供一个可编辑正文，以及一份便于律师复核的核验说明；简单修改可直接更新尚未送审的工作稿。核验说明记录本版文件名、原始要求、关键前提、正文位置对应的原文与来源、实际核验结果、待确认项和本轮修改，足够独立复核即可，不重复整篇正文。有关原始材料保留在授权位置，交接给另一对话时核实可访问性。

短篇事实整理、邮件措辞或少量改写，可在同一文件末尾附简短来源及范围说明，提供原材料定位；材料只在对话中时可附所给原句，不为几句话默认另建核验表、原文副本和第三个附件。用户要求保留依据，先选择足够复核的最简方式。事实整理的来源说明不用逐句重复“未独立核验”；准确交代一次即可。需要多处法律引注、相反依据或复杂修订记录时再展开。

已经要求双视图的任务继续提供同版核验稿和纯净稿；已登记事项沿用项目双文件规则。其他任务不另造 BRIEF、RESPONSE、引用 JSON、状态 JSON 和多份同内容正文。技术记录不能替代原文与分析；两种交付方式使用相同核验标准。

保存送审版本后，正文、依据或核验说明改变就保存新版本，保留旧版及对应意见，不用文件名中的“最终版”代表已批准。并行写入、多人持续管理或用户明确要求封存历史时，使用已有的项目版本能力；当前任务尚未需要时不初始化。

同一事项可以有律师函、备忘录等不同成果；它们分别登记用途与视图，核对共同事实、条件和行动相容性，不要求正文一致。正式目录只保存已确认的指定成果，内部说明和意见留在事项中。

## Word 与展示

用户指定格式或所内模板优先。成篇法律意见、报告、函件默认优先 `.docx`；用宿主实际可用的文档技能／工具完成生成、排版和预览，读取它的实际规则。千问已有 docx 能力时直接复用，不要求律师安装 Python、Pandoc 或运行转换脚本，也不为每次任务重写转换器。

Word 保留所选文种的段落结构、中文字体、表格、引注及必要限定。采用脚注体例时，支持原生脚注就使用，退为尾注时标明，不把正文中的 `[^1]` 当作原生脚注；律师函按 [lawyer-letters.md](lawyer-letters.md) 正文直引，不自动补脚注或尾注，也不套报告编号大标题。导出后核对内容和可用的页面预览；转换成功不代表引注或分页正确。不能生成 Word 时交付可编辑文本并说明当前格式能力缺口；不能预览时说明“页面未核验”，不谎称已生成或检查附件。

受管理项目在送审前固定候选 Word。律师确认覆盖该文件，发布只复制，不临时改写、重新排版或转换格式；确需改变候选文件时重新保存版本并检查受影响内容及必要页面，再取得本版确认。

对话优先链接当前正文，附核验说明／审阅意见，只解释影响使用的结果与缺口。文件名用清楚、简短的中文即可，沿用用户命名；不展示中间代码、完整 XML、目录树或工具日志。原始证据数量按需要保留，不为凑成两个文件而删证据。

## 审阅如何接续

另一个实际对话读取文稿、核验说明和所引原文，输出一份“审阅意见”，记录所审文件／版本、检查范围、问题位置、证据、解决条件和总体结论。仅审一份文稿时，多视图比对可记不适用；受委托的原文或法律检查不能因此省略。已有双视图要求而缺一份时，记录缺件。

下一次修订由生成侧直接读取意见；审阅侧复核新稿后确认解决或撤回误报。只检查指定段落或没有完成必要核验时，只给相应范围结论。共享文件本身不自动启动另一对话；无共享能力时才说明所需材料，不能让律师重复提供已经可访问的文件。
