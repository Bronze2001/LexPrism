# 原始问题受理与样本文书适配

## 从口语请求确定工作

保留用户原始问题，识别服务对象／立场、法域、实际要作的决定、已知事实和交付物。问题表述零散或不专业时，先整理出可回答的问题；不能把推测出的事实当成用户已确认信息。仅追问会改变法律分析、检索范围或文种的关键缺项，并继续处理已明确部分。

用户已指明特定法律身份或事项时，先以该身份作明确的分析前提；必要的证件核实可以提示，但没有相反事实时，不把其他主体形态扩成平行长篇报告。将“直接回答”“影响答案的必要关联”“可选延伸”分开，正文集中回答前两者；税务、外汇、其他法域等延伸须说明与本题的具体联系。主事实未定时只展开会改变答案的分支，不能把假设分支写成已确认主体。

按用户目的选文种，明确指定优先于自动判断：

| 用户要解决的问题 | 默认适配方向 | 核心内容 |
| --- | --- | --- |
| 查规定、权利义务、监管要求 | 法律检索报告／规则整理 | 分问题法源与适用分析、具体义务及精炼检索结论 |
| 回答客户具体问题、提供内部意见 | 法律回复／法律意见 | 事实前提、适用依据、逐项回答、风险及行动 |
| 怎么沟通、下一步如何应对 | 法律应对／风险研判 | 备选行动、各自条件和风险、补件及沟通要点 |
| 向对方正式主张、催告或答复 | 律师函／回复函 | 发送人和收件人、已证实事实、主张、具体请求与期限依据 |
| 核查企业或交易材料 | 尽调报告 | 核查范围、材料状态、发现及依据、风险、补件；不把缺件当无问题 |
| 资产价值相关法律问题 | 法律层面的资产风险分析 | 权属、负担、处置限制；未具备估值数据及专业依据不输出伪造的评估价或资质结论 |
| 审核、修改合同 | 合同审查流程 | 按 contract-review.md 处理立场、31 项清单和修改建议 |

一句话涉及多种交付物时可组合，但不默认把每个请求扩成整套报告、函件和图表。区分事实问题、实体义务、程序／监管权限问题，识别监管机关的层级、权限与交叉管辖；问题树围绕决定性要素构建，不只按关键词搜材料。

## 样本模仿

缺少匹配样本或现有指导不足时，按 [reference-learning.md](reference-learning.md) 自主寻找专业参考，提炼结构、文风和判断方法，再经原有引用标准核验。评委文章与比赛范围截图可辅助理解产品目标，不自动成为正式评分细则或本案法律依据。

收到样本后先提取其标题层级、章节顺序、段落功能、称谓与语气、术语、论证顺序、引注及结尾方式，建立简短的样式记录，再写本案内容。样式记录不必强行插入正式文书。

记录样本各部分在本案中的对应内容或不适用理由。保留用户明确要求的结构，允许按本案主题、材料完整度、问题层级和文种调整其余部分；只有低等级来源或缺案例时不为填模板编造事实、法律或案例。范例中的人物、金额、日期、案号、法域和法律结论不自动继承。范例带专家批评时保留其适用的样式优点，修正被批评的方法，不能照抄被指出的问题。

人工精修或实务报告是风格与工作目标的参考，不自动等于穷尽、现行或无误的法律标准。分别评价其可复用结构、事实／法源内容和格式缺口；保留有价值的“检索问题—相关原文—针对性结论”关系，但不要把样本漏项、错号、资料分类或缺少链接带入新稿。没有人工对照的题目以任务完成度、原始法源和 Skill 约束评价，不用与样本的文字相似度替代正确性。

不同样本冲突时按本次指定优先级处理；没有优先级且影响交付时提出必要问题。材料缺失时不声称已读取或复刻该样本。正式写作与引用规则按 [drafting-review.md](drafting-review.md)，收到后续事实或法律材料时按 [supplemental-materials.md](supplemental-materials.md) 更新。
