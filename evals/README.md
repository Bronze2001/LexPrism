# 专家评测与反馈

本目录提供记录约定，不含已通过的评测结果，也没有把香港样例加工成标准法律答案。

## 案例组织

真实或脱敏案例在`private/evals/<case_id>/`维护题目、材料目录、允许的来源范围、法域/时点、交付标准和专家意见。运行输出存`runs/<case_id>/<run_id>/`。这两个目录已加入忽略规则；公开示例必须另行检查可分享范围。

香港样例是已看过专家反馈的开发案例；保留原答案和原评语，不将全部答案视为已被专家认可。今后每个专家案例独立编号。真实客户材料与合成练习分别标记。新增法域不会自动继承其他案例的实体法律结论。

建议首轮10个槽位：合同3、尽调/合规3、法律研究回复1、事实证据2、争点类案1。当前尚未填满，这是准备配额，不是成绩。案例条件允许时留出至少一个非诉和一个争议案例作保留集；若已经用其反馈调过技能，则移回开发集并补充新的保留案例。

## 逐例评价

| 维度 | 记录方式 |
| --- | --- |
| 法律与事实准确性 | 逐项错误、严重程度、需改的主张；不要只给综合印象分 |
| 来源与定位 | 实际检查的引用数量、可取得/可定位数量及不支持主张的实例 |
| 覆盖与适用 | 是否漏关键争点、例外、不利材料、时点/主体条件 |
| 建议与文种 | 建议是否可执行，文字是否适合客户、内部备忘或法院文书 |
| 修改成本 | 专家实际用时或“未计时”；轻改/重写/不可用及原因 |
| 复现性 | 输入、技能、工具、模型可见配置是否留存，重跑有何差异 |

建议可用性标签：`usable_with_minor_edits`、`needs_substantial_revision`、`unusable`、`not_reviewed`。这不是自动分数；由评审人判定。引用比例必须说明分母是否为全部实质法律主张、全部引文或抽样引文。严重错误不得被平均分掩盖。

## 反馈采纳

复制[反馈模板](templates/feedback.template.json)，保留原话、答案版本和位置。category可用：事实、来源、定位、时效、法律推理、覆盖、建议、结构、语言、工具、其他。scope可用：`case`、`document_type`、`business_domain`、`jurisdiction`、`reviewer_preference`、`global_candidate`、`pending`。

本案内容错误只改本案。文种和个人偏好按场景应用。跨案例重复出现的方法问题才适合成为全局候选，经确认并回归后进入技能版本。记录采纳、部分采纳、拒绝或待定及理由；不同专家意见分开保存。模型自评不是律师评审，尚未运行的回归必须标`not_run`。

复制[运行模板](templates/run.template.json)，填写真实记录并将record_type改为`run`；反馈记录改为`expert_feedback`。模板null和空数组只是占位，不代表没有错误或调用成功。source_mode建议用`provided_only`或`authorized_retrieval`；condition用`baseline`或`lexprism`。

一个最小sources条目应有source_id、provider、标题、content_kind、URL/本地许可位置、版本/日期、取得状态；claims条目应有claim_id、文本/段落、事实前提、source/passage关联与核验状态。后续程序化校验应基于真实输出固定结构，再引入严格schema，避免目前用空壳校验制造可靠性。

## 对照与回归

同一材料、可见模型配置和工具权限下保存基线与Skill输出；换输入再测。不要将先前看到答案的测试称为盲测。每次修订运行受影响案例，并至少检查另一个未用于该修改的案例是否退化。报告明确样本数、未评审数、失败原因和未覆盖范围；当前没有可公布的通过率。
